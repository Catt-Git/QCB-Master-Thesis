# datasets (`DATA_DIR`)

Where every heavy object of the thesis lives. The scripts never hardcode this path: they read
`DATA_DIR` from the environment and exit with an explanatory message if it is unset.

```bash
export DATA_DIR=~/Desktop/QCB-Master-Thesis/datasets
```

**One `DATA_DIR` for the whole pipeline.** Phases 00 to 05 read and write the *same* root, in
the per-phase subfolders listed below, and each phase's first input is the previous phase's
output at that same root. The value changes between machines, never between phases: a second
root anywhere in the chain breaks the 00 → 01 and 01 → 02 hand-offs, since 01_2 looks for
`all_samples_combined.h5ad` exactly where 00_6 wrote it.

The clone itself can sit anywhere: no script contains the repo's path (they self-locate via
`SCRIPT_DIR` / `SLURM_SUBMIT_DIR`), so `DATA_DIR` is the only thing to set after `git clone`.
On the cluster the root is `/users/genomics/albertoc/Tesi/hopes_and_dreams/datasets`: outside
the clone on purpose, because 2.4 TB inside a git working tree means `git status` stats all of
it. Linking it into the clone keeps the export line identical on both machines:

```bash
ln -s /users/genomics/albertoc/Tesi/hopes_and_dreams/datasets <clone>/datasets
export DATA_DIR=<clone>/datasets
```

The Cell Ranger reference (`REF`, ~11 GB, `submit_cellranger.slurm`) stays outside `DATA_DIR`:
it is a shared external input, not something a phase of this pipeline writes. The exact build used
here is 10x Genomics' prebuilt human reference `refdata-cellranger-GRCh38-3.0.0` (the same as the
paper), downloadable with
`curl -O https://cf.10xgenomics.com/supp/cell-exp/refdata-cellranger-GRCh38-3.0.0.tar.gz` and then
untarred: `REF` points at the resulting directory.


**Almost nothing here is in git.** `.gitignore` excludes `/datasets/*` - the objects run to tens
of GB, well past GitHub's 100 MB per-file limit - with four exceptions, the small inputs that
cannot be regenerated by the code: this README, `Cells_Adult_Breast.pkl` (the CellTypist model),
`regev_lab_cell_cycle_genes.txt` (the Tirosh/Regev signature) and `signatures/` (the curated gene
lists read by 04_3, see below). Everything else is rebuilt by re-running the phase that writes it.

Three collections live here: the 11 stemness/immunogenicity lists (`--collection scie`), the 9 `EMT_[ABC]_*` ones (`--collection emt`, documented in `signatures/EMT_LISTS_NOTES.md`), and the 41 pan-cancer metaprograms of Gavish et al. 2023 in the `signatures/GAVISH_metaprograms/` subdirectory (`--collection gavish`, 24 of them scored by default), written by `05_drvi_tumoral_epi/utils/gavish_extraction.py` — one `.txt` per metaprogram, same one-symbol-per-line format. Forty of them are extracted from `GAVISH.csv`; `MP1` (Cell Cycle - G2/M) is absent from that CSV and from the MSigDB release behind it, so that one list is hard-coded in the same script from the authors' `MP_list.RDS` (github.com/tiroshlab/3ca), in the paper's own gene symbols. |

### 06_ambient_soupx

`06_amb/` holds everything phase 06 writes, and is also a **`DATA_DIR` in its own right**: the
corrected object is deliberately called `shiao.h5ad`, so exporting `DATA_DIR=$DATA_DIR/06_amb`
re-runs phase 05 on the ambient-corrected data with no change to any script. See
`06_ambient_soupx/utils/link_shadow_data_dir.sh`, which symlinks the auxiliary inputs 05 also
expects into it.

| Path | Step |
|---|---|
| `06_amb/soup/<sample>.csv.gz` | 06_1, the empty-droplet profile of one channel (~300 KB) - the only thing that comes off the cluster |
| `06_amb/soup_census.csv` | 06_1, droplets in the soup range and UMIs per channel |
| `06_amb/input/genes.tsv`, `06_amb/input/<sample>/` | 06_2, the gzipped Python→R handoff - removable with `soupx_all.sh --clean` |
| `06_amb/adjusted/<sample>/removed.mtx.gz` | 06_2, the counts SoupX took out (the delta, not the adjusted matrix) |
| `06_amb/adjusted/<sample>/rho.csv`, `cells.csv` | 06_2, the estimate per channel and the UMI totals per cell |
| `06_amb/soupx_rho.csv` | 06_2, those merged - one row per channel, with how rho was obtained |
| `06_amb/soupx_cells.csv` | 06_2, one row per cell: `soupx_frac_removed` and what it was computed from - what the 06_3 notebook reads |
| `06_amb/shiao_soupx_all_cells.h5ad` | 06_2, all 619,693 cells, corrected, nothing dropped |
| **`06_amb/ambient_keep.csv`** | 06_3, the call - one boolean per cell, with the reason columns |
| `06_amb/cell_annotation_soupx.csv` | 06_4, phase-01 label vs the label on corrected counts |
| **`06_amb/shiao.h5ad`** | 06_4, the drop-in replacement for `shiao.h5ad` |
| `06_amb/Cells_Adult_Breast.pkl`, `regev_lab_cell_cycle_genes.txt`, `signatures/` | symlinks, made by `link_shadow_data_dir.sh` |
| `06_amb/05_tum/` | phase **05** re-run with `DATA_DIR=$DATA_DIR/06_amb`; `datasets/05_tum/` is untouched |

In `06_amb/shiao.h5ad`, `.X` holds the corrected **counts** rather than a normalisation, and
`obs['size_factors']` is gone: correcting the counts invalidates the phase-01 scran factors, and
re-running scran on 619,693 cells is 01_3's 470 GB job. 05_2 copies `layers['counts']` into `.X`
and re-runs scran on its own subset anyway. `uns['ambient_soupx']` records this in the object.

## Disk

Budget a few hundred GB for phases 01-04, and ~2.4 TB more if the FASTQ of phase 00 are kept.
The heaviest single items are the scaled Seurat object (11 GB), the `full`-type integrations
(8-10 GB each) and the DRVI latent objects (~730 MB at `n_latent=128`).

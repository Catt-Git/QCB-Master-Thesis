# datasets (`DATA_DIR`)

Where every heavy object of the thesis lives. The scripts never hardcode this path: they read
`DATA_DIR` from the environment and exit with an explanatory message if it is unset.

```bash
export DATA_DIR=~/Desktop/QCB-Master-Thesis/datasets
```

**One `DATA_DIR` for the whole pipeline.** Phases 00 to 05 read and write the *same* root, in
the per-phase subfolders listed below, and each phase's first input is the previous phase's
output at that same root. The value changes between machines, never between phases: a second
root anywhere in the chain breaks the 00 → 01 and 01 → 02 hand-offs, since 01_2 looks for
`all_samples_combined.h5ad` exactly where 00_6 wrote it.

The clone itself can sit anywhere: no script contains the repo's path (they self-locate via
`SCRIPT_DIR` / `SLURM_SUBMIT_DIR`), so `DATA_DIR` is the only thing to set after `git clone`.
On the cluster the root is `/users/genomics/albertoc/Tesi/hopes_and_dreams/datasets`: outside
the clone on purpose, because 2.4 TB inside a git working tree means `git status` stats all of
it. Linking it into the clone keeps the export line identical on both machines:

```bash
ln -s /users/genomics/albertoc/Tesi/hopes_and_dreams/datasets <clone>/datasets
export DATA_DIR=<clone>/datasets
```

The Cell Ranger reference (`REF`, ~11 GB, `submit_cellranger.slurm`) stays outside `DATA_DIR`:
it is a shared external input, not something a phase of this pipeline writes. The exact build used
here is 10x Genomics' prebuilt human reference `refdata-cellranger-GRCh38-3.0.0` (the same as the
paper), downloadable with
`curl -O https://cf.10xgenomics.com/supp/cell-exp/refdata-cellranger-GRCh38-3.0.0.tar.gz` and then
untarred: `REF` points at the resulting directory.


**Almost nothing here is in git.** `.gitignore` excludes `/datasets/*` - the objects run to tens
of GB, well past GitHub's 100 MB per-file limit - with four exceptions, the small inputs that
cannot be regenerated by the code: this README, `Cells_Adult_Breast.pkl` (the CellTypist model),
`regev_lab_cell_cycle_genes.txt` (the Tirosh/Regev signature) and `signatures/` (the curated gene
lists read by 04_3, see below). Everything else is rebuilt by re-running the phase that writes it.

## What each phase writes here

### 00_raw_data_processing

| Path | Step |
|---|---|
| `fastq_raw/` | 00_3, the FASTQ as downloaded (~2.4 TB) |
| `renamed_fastq/` | 00_4, Cell Ranger naming + `unique_samples.txt` |
| `cellranger_out/<sample>/outs/filtered_feature_bc_matrix.h5` | 00_5 |
| `all_samples_combined.h5ad` | 00_6, the concatenated raw object |

### 01_pre_processing

| File | Step |
|---|---|
| `all_samples_combined_scrublet.h5ad` | 01_2, QC + Scrublet + filters |
| `all_samples_combined_scrublet_norm.h5ad` | 01_3, scran log-normalization |
| `all_samples_combined_scrublet_norm_cc.h5ad` | 01_4, + cell cycle |
| `..._cc_annotated.h5ad` | 01_4, + CellTypist (`fraction` recoded in place) |
| `..._cc_annotated_reduced.h5ad` | 01_5, + HVG / PCA / neighbours / UMAP |
| `shiao_hvg_2k_unintegrated_list.csv` | 01_5, the 2,000 HVG symbols |
| **`shiao.h5ad`** | 01_5, + leiden - **the definitive unintegrated object** (619,693 x 30,869) |

Auxiliary inputs read from here: `regev_lab_cell_cycle_genes.txt` (via `CC_GENES`) and
`Cells_Adult_Breast.pkl`.

### 02_integration_benchmark

| Path | Step |
|---|---|
| `shiao_hvg_2k.h5ad` / `shiao_hvg_2k_scaled.h5ad` | 02_1, the two Python inputs |
| `shiao_hvg_2k.rds` / `shiao_hvg_2k_scaled.rds` | 02_1, the same two for the R methods |
| `shiao_hvg_2k_unintegrated_list.rds` | 02_1, the HVG symbols for the Seurat anchors |
| `02_integration/<run_id>.h5ad` | 02_2, the integrated objects |
| `02_embeddings/<run_id>.npy` | 02_2, latent spaces kept for the figures |
| `02_scvi/`, `02_scanvi/`, `02_scgen/`, `02_drvi/` | 02_2, one flat directory per trained method |
| `02_metrics/shiao/metrics/<scaling>/hvg/<method>_<type>.csv` | 02_4, per-run metric CSVs |
| `02_metrics_merged.csv` | 02_4, the merged table behind the summary figure |

The trained methods keep their model out of `02_integration/` on purpose, so that directory holds
exactly what the metrics read. See "Trained models" in the phase-02 README.

The R methods also write a `02_integration/<run_id>.rds` intermediate, deleted once converted
(`--keep-rds` to keep it): nothing downstream reads it and it is the largest artefact of the phase.

### 05_epi_treatment

One folder per treatment split, `<split>` being `base`, `pd1` or `rtpd1`.

| Path | Step |
|---|---|
| `05_epi_treat/<split>/shiao_epi_<split>_raw.h5ad` | 05_1, the split of `04_epi/shiao_epi_raw.h5ad` + refilter |
| `05_epi_treat/<split>/shiao_epi_<split>_norm.h5ad`, `..._norm_cc.h5ad`, `..._reduced.h5ad` | 05_1 |
| `05_epi_treat/<split>/shiao_epi_<split>_hvg_2k_list.csv` / `shiao_epi_<split>_hvg_2k.h5ad` | 05_1, the DRVI input, HVGs reselected inside the split |
| **`05_epi_treat/<split>/shiao_epi_<split>.h5ad`** | 05_1, + leiden - the definitive object of the split |
| `05_epi_treat/<split>/model_drvi_epi_<split>_<N>.pt` | 05_2, the trained DRVI model, one flat file per run |
| `05_epi_treat/<split>/embed_drvi_epi_<split>_<N>.h5ad` | 05_2, latent space + per-dimension stats + OOD/IND scores - what `drvi_treat.ipynb` reads |
| `05_epi_treat/<split>/shiao_epi_<split>_drvi_epi_<split>_<N>.h5ad` | 05_2, the 05_1 object (all genes) + `obsm['X_drvi']` |

The three splits together are the 74,441 cells of `04_epi/shiao_epi.h5ad` minus the per-split
cohort drops, so this folder roughly doubles the epithelial footprint on disk.

## Smoke-test artifacts

All disposable, all regenerated by the smoke tests themselves (see the phase-02 README):
`smoke_fixture.h5ad`, `smoke_hvg.h5ad` / `.rds`, `smoke_hvg_list.csv` / `.rds`, `smoke_out/`,
`smoke_metrics/`, `smoke_metrics_merged.csv`.

## Disk

Budget a few hundred GB for phases 01-04, and ~2.4 TB more if the FASTQ of phase 00 are kept.
The heaviest single items are the scaled Seurat object (11 GB), the `full`-type integrations
(8-10 GB each) and the DRVI latent objects (~730 MB at `n_latent=128`).
